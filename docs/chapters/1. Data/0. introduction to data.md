# Introduction to Data
Welcome to data. In this context, *data* refers to the collection of observations or measurements that we use to train, test, and validate our models. While algorithms often get the spotlight, data is arguably the most important part of everything we do in AI. The performance of any model is heavily influenced by both the quality and quantity of the data it learns from.

In a university setting, we’re often lucky. Datasets are usually provided for us, they’re clean enough to work with, and they contain the information we need to complete an assignment successfully. This makes it easy to focus on learning the mechanics of an algorithm without worrying too much about where the data came from. In the real world, things are rarely that simple. Data can be difficult to collect, incomplete, or missing important information altogether. You might have too little data, poorly chosen features, or measurements that don’t quite capture what you care about.

This section of the notes is designed to help you build good intuition around data, how to work with what you’re given, and how to make sensible decisions even when the data is imperfect. Getting this part right will make every model you build more reliable, interpretable, and useful.

## Common Terminology
Before we go any further, let’s quickly define a few terms that will appear constantly throughout these notes.

#### Observations (Data Points)
An observation, also called a data point, corresponds to a single example in your dataset. In a table, this is typically a single row. 

As an example, an observation could look like:

| Student ID | First Name | Last Name | Gender |
| :----------: | :----------: | :---------: | :------: |
| 12345678 | Adam | Smith | Male |

where all the information above relates to the same person.

#### Features
A feature is an individual measurable property of an observation. In the table above, the features would be "Student ID", "First Name", "Last Name" and "Gender". Features are usually stored as columns.

#### Labels (Targets)
A label (or target) is the value we want to predict.

## Types of Data
The type of data you are working with influences how you store it, how you explore it, and which models are appropriate. Before building anything, it’s worth understanding what kind of data you actually have in front of you. Most of the data you will encounter can be grouped into a few broad categories.

### Structured Data
Structured data is the most common starting point, especially in coursework and early projects. This is data that fits neatly into a table, where each row represents an observation and each column represents a feature. Here is an example of structured data

| Index | Height (cm) | Weight (kg) |
| :-----: | :------: | :------: |
| 1 | 177 | ------ |
| 2 | 191 | ------ |
| 3 | 173 | ------ |
| 4 | 158 | ------ |
| 5 | 167 | ------ |
| ----- | ------ | ------ |

### Unstructured Data
Unstructured data does not naturally fit into rows and columns. Instead, it often comes in forms like text, images, audio, or video.

### Categorical and Numerical Data
Regardless of whether data is structured or unstructured, features themselves can usually be described as either numerical or categorical. 

**Numerical data** represents quantities that can be measured, such as height, temperature, or time. **Categorical data** represents groupings or labels, such as colour, country, or product type.

Handling categorical data often requires additional processing, such as encoding categories as numbers, which will be covered further on within these notes. 

!!! warning "Note"

    Treating categorical values as raw numbers without care can lead to misleading results. It is common practice to label binary results as "1" or "0". These results are categorical values, and should not be treated as numbers.
